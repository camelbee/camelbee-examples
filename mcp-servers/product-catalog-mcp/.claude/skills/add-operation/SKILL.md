## Checklist

### 1. API Specification
- [ ] Add new path/operation to `openapi/order-api.yaml` (or `.proto`/`.avsc`/`.wsdl`)
- [ ] Set `operationId: {operationName}` — this becomes the route entry point
- [ ] Define request/response schemas
- [ ] Run `./mvnw generate-sources` to regenerate API models

### 2. Consumer Routes
- [ ] Add handler in each consumer route that should support this operation
- [ ] For REST: the OpenAPI `operationId` creates `from("direct:{operationName}")`
- [ ] For messaging (Kafka, AMQP, JMS, etc.): add topic/queue configuration
- [ ] Unmarshal → validate → map API→Domain → route to `direct:central{OperationName}`

### 3. Central Route
- [ ] Create `routes/central/Central{OperationName}Route.java`
- [ ] Must use `errorHandler(noErrorHandler())`
- [ ] Store original body: `.setProperty(Constants.ORIGINAL_BODY, body())`
- [ ] Fan-out to all configured backends with `.to("direct:{operationName}{Technology}").id("{operationName}{Technology}Endpoint")`
- [ ] Set response: `.setBody(exchangeProperty(Constants.ACTUAL_RESPONSE_BODY))`

### 4. Producer Routes
- [ ] Add handler for the new operation in each producer route
- [ ] Retrieve body from `Constants.ORIGINAL_BODY`
- [ ] Map Domain→Infra, call backend, map response back
- [ ] Store response in `Constants.ACTUAL_RESPONSE_BODY`

### 5. Configuration
- [ ] Add topic/queue names in `application.yml` if messaging
- [ ] Add backend endpoint properties if needed

### 6. Unit Tests (MUST include success + error)
- [ ] Create `Central{OperationName}RouteUnitTest.java`
- [ ] Add AdviceWith mocks for all backend endpoints (`weaveById`)
- [ ] **At least 1 success test** — verify the happy path with mocked backend returning expected response
- [ ] **At least 1 error test** — verify error handling (e.g., backend returns error, validation failure)
- [ ] Follow the exact same structure as existing `Central*RouteUnitTest` files

### 7. Integration Tests (MUST include success + error)
- [ ] Create `{OperationName}IntegrationTest.java` (or add to existing files)
- [ ] Use `@ParameterizedTest` + `@MethodSource` for multi-format testing
- [ ] **At least 1 success test** — set up backend test data (WireMock stubs, DB records, queue messages), send request, verify backends received correct data via mock capture endpoints and data verification
- [ ] **At least 1 error test** — verify error scenarios (backend failure, validation error)
- [ ] Add test data files in `src/integration-test/resources/data/`
- [ ] Do NOT skip success tests because backend setup is complex — study existing integration tests for how to set up test data

### 8. Black-box Tests (MUST include success + error)
- [ ] Create `{Protocol}{OperationName}BlackBoxTest.java`
- [ ] **At least 1 success test** — send request via protocol, verify response AND verify backend received data using data verifiers
- [ ] **At least 1 error test** — verify error response for invalid input or backend failure
- [ ] Do NOT skip success tests — study existing black-box tests for backend data setup and verification patterns

### 9. Verify
- [ ] `./mvnw test` — all unit tests pass
- [ ] `./mvnw jacoco:prepare-agent failsafe:integration-test failsafe:verify` — all integration tests pass
- [ ] `./mvnw verify -Pblack-box-test` — all black-box tests pass
